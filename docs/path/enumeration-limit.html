Why the first enumeration could not give the next bound

Earlier result; a boundary of one method

The question

A tight counting argument for an explicit enumeration rule is not a lower bound for the equivalence problem.

How it works

  1. The earlier algorithm fixes frequent names. A stronger obstruction covers any explicit branching by variable fixings: each leaf must admit a schedule with at most k layers of each label. Let a selector choose q affine orders of q² bits in a block. Two distinct orders have a common subsequence of at most 2q−1, so counting overlaps shows that a read-k schedule can keep only O(kq) labels free per block while all selector modes survive.
  2. On equivalent input diagrams, the selector can be made to depend on many controls. Each permitted leaf then fixes either a linear number of controls or a linear number of data bits. At the earlier cutoff k=Θ(log log N), suitable graph sizes force 2Ω(N/log log N) explicit leaves.
  3. This is not a lower bound on deciding equivalence. The separate input-reading argument uses encodings of permutations and an equality fooling set to give Ω(N log N) bit probes or Ω(N) word probes in the stated indexed-record model.

What carries forward

This is motivation for a different method, not a premise in the proof of the improved time bound. Do not confuse it with the later Cartesian-product lower bound.
